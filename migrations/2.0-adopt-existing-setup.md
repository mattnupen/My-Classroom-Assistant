# Migration: pre-2.0 → 2.0 — adopt an existing classroom into `my-classroom/`

**Audience:** the Claude agent running an update in a teacher's project folder.
**Applies when:** `my-classroom/` does not exist, AND the folder shows signs of a live pre-2.0 setup — for example `brain/your-classroom-ai.md` exists with real content (no `[AI NAME]`-style brackets), or `brain/class-story.md` has entries, or `local-tools/` contains app folders not in the shipped sidebar list.
**If it doesn't apply** (fresh install, or `my-classroom/` already exists): skip this file entirely and say nothing about it.

Every step below is check-then-act. Re-running this migration on an already-migrated folder must change nothing.

## Step 0 — Backup, always

Ask the teacher to duplicate the entire project folder in Finder/Explorer. Wait for explicit confirmation. Do not proceed without it. This migration **copies** — it deletes nothing until the very last step, and only with permission.

## Step 1 — Create the classroom folder

If `my-classroom/` doesn't exist, copy `my-classroom.example/` to `my-classroom/`.

## Step 2 — Adopt the persona and the story

- If the old `brain/your-classroom-ai.md` exists and has real content: copy it over `my-classroom/your-classroom-ai.md`.
- If the old `brain/class-story.md` has entries: copy it over `my-classroom/class-story.md`.
- If either is still the blank template, keep the fresh template copy and move on.

## Step 3 — Adopt the dashboard cards

Open `local-tools/ClassAI-dashboard.html` (as a file — do not launch it) and find the inline `<script type="application/json" id="dashboard-data">` block. If its content differs from the shipped default (i.e., it describes a real class), port that JSON into `my-classroom/dashboard-data.js` as the `window.DASHBOARD_DATA` assignment, content verbatim, schema unchanged. Leave the `dashboard-demo-data` block alone in all cases.

## Step 4 — Adopt teacher-built apps

List the subfolders of `local-tools/` containing an `app.html`. Any whose slug is **not** in `_nav.js`'s `DEFAULT_APPS` is teacher-built:

1. Copy each to `my-classroom/apps/<slug>/` (including any `sandbox.csv`).
2. Add each to `my-classroom/my-apps.js` with `file: "../my-classroom/apps/<slug>/app.html"`, label and description taken from the app's own `<h1>`/`<h2>` or the old manifest/nav entry if one exists.
3. If a pre-2.0 `local-tools/manifest.json` exists, use it as a cross-check for labels, then note it for deletion in Step 7 — nothing reads it in 2.0.
4. Each adopted app lacks a `spec.md`. Create one containing: "Adopted from a pre-2.0 install on [date]. Original spec not recorded — describe this app to me if you'd ever like it rebuilt on a newer scaffold." Do not guess at a spec.

## Step 5 — Record the data policy

The pre-2.0 architecture was Locked-Room only, so write `my-classroom/data-policy.md` as Locked-Room mode with today's date and the note "carried over from pre-2.0 setup." Then tell the teacher, in one sentence, that a district-approved Direct mode now exists and where to read about it — do not pitch it, do not ask them to decide now.

## Step 6 — Stamp and verify

Write the engine `VERSION` into `my-classroom/.installed-version`, then run the full doctor check from `CLAUDE.md`. Fix what it flags (with confirmation) until it passes.

## Step 7 — Cleanup, with permission

Only after the doctor passes, list the originals now duplicated — the old `brain/your-classroom-ai.md` and `class-story.md`, adopted app folders under `local-tools/`, any `manifest.json` — and ask the teacher whether to remove them. If they hesitate, leave everything and note in `class-story.md` that duplicates remain.

## Step 8 — Tell the story

Report in plain language: what was adopted, where it lives now, and the one-sentence version of what 2.0 means for them — *"your classroom now lives in one folder that updates will never touch; copying that folder is a full backup."* Append a one-line entry to `my-classroom/class-story.md` noting the migration date.
